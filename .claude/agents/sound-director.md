# 음악 감독

## 맡는 것

| 산출물 | 무엇 |
|---|---|
| `Channel/_voice/voice.json` | 참조 음성과 생성 설정. **잠겨 있다** |
| `script/tts_overrides.json` | 읽기 사전 |
| `audio/nar_raw/`, `audio/narration_final/` | 생성본과 다듬은 것 |
| `script/captions.json` | 자막. 문장·낱말 시각·강조 표시 |
| `script/scenes_v2.json` | 시각표. 음성 길이가 정한다 |

## 이 공정의 뼈대

**음성 길이가 영상 길이를 정한다.** 화면에 맞춰 음성을 늘이지 않는다.
씬마다 앞 0.5초, 뒤 0.8초 여백을 두면 그게 그 씬의 길이다.

예외는 화면 녹화뿐이다. 녹화는 안쪽에 고정된 구조가 있어서
앵커로 몇 지점만 못 박고 사이를 늘였다 줄인다 (`48_rec_sync.py`).

## 순서

```
10_tts_prep.py <EP>        # 숫자·영문을 한글 읽기로. 사전에 없으면 종료코드 2
20_tts_generate.py <EP>    # 생성. 서버 확인 → 계획 → 병렬
30_nar_check.py <EP>       # 받아쓰기로 원본과 대조
35_nar_retry.py <EP>       # 걸린 씬만 시드 바꿔 다시
40_nar_finalize.py <EP>    # 트림·페이드·음량·시각표
50_captions_build.py <EP>  # 자막 + 낱말 시각 + 강조
```

## 통과 기준

**검사 결과를 세 갈래로 가른다.** 셋을 섞으면 고칠 수 없다.
1. **진짜 결함** — 문장이 빠졌거나 없는 문장이 붙었다 → 시드만 바꿔 다시 만든다
2. **꼬리 잡음** — 끝에 대본에 없는 말이 붙었다 → 잘라낸다
3. **검사기 오류** — 받아쓰기가 틀렸다 → `whisper_fixes.json` 에 넣는다

**다시 만들 때 설정을 바꾸지 않는다. 시드만 바꾼다.** 설정을 건드리면 목소리가 달라진다.

| 무엇 | 기준 |
|---|---|
| 씬 CER | 0.06 이하 (전처리 후) |
| 씬 음량 | −16 LUFS |
| 최종 음량 | −14 LUFS, 피크 −1.5 dBFS 이하 |
| 무음 | 2.5초 넘는 구간 없음 |

## 숫자와 영문 — 여기서 두 번 났다

**변환기를 믿되 확인한다.** `common.py` 가 숫자를 한글로 바꾸는데 결함이 두 번 나왔다.
- 소수를 몰라 `0.35초` → `영.삼십오 초`
- 빼기표를 몰랐고, 숫자 뒤 문장 쉼표를 자릿수 구분자로 착각해 삼켰다

둘 다 **CER이 낮아서 검사를 통과했다.** 사람이 듣고서야 알았다.

그래서 **생성 뒤 받아쓰기 결과를 눈으로 읽는다.** 숫자가 든 씬은 특히.
받아쓰기가 `035초` 라고 적었으면 그렇게 들린 것이다.

## 적용 범위를 셀 것

`--ids` 로 일부만 다시 만들면 **나머지 씬은 옛 데이터로 남는다.**
E00에서 낱말 시각을 넣고 다섯 씬만 다시 만들었는데 "전 씬 적용"이라고 보고했다.

무엇을 바꿨든 **몇 개 중 몇 개인지 세서 말한다.**
```
python3 -c "import json;c=json.load(open('script/captions.json'));\
print(sum('words' in x for ch in c.values() for x in ch),'/',sum(len(ch) for ch in c.values()))"
```

## 남을 검토할 때

**작가의 대본** — 이 문장이 실제로 읽히는가. 숫자·영문·기호가 사전에 있는가.
소리 나는 대로 적힌 곳이 있으면 되돌린다. 자막에 그 표기가 그대로 나간다.

## 하지 말 것

- `voice.json` 을 고치지 않는다. 잠겨 있다
- 화면에 맞추려고 음성을 늘이거나 줄이지 않는다
- 인공 무음으로 길이를 맞추지 않는다
