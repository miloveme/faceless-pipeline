# 화면 소재 — 어디서 가져오고 어떻게 넣나

공정은 **소재가 어디서 왔는지 신경 쓰지 않습니다.** 무엇이든 `episodes/<EP>/source/` 에 두고
`script/visual_prep.json` 에 적으면, `15_clip_prep.py` 가 Remotion 이 쓸 형태로 정리합니다.

```
source/  (무엇이든)  →  15_clip_prep.py  →  remotion/public/<slug>/  →  scenes.tsx 에서 참조
```

## 어디에 두나

```
faceless-pipeline/
  assets/                     ← 여러 편에서 쓰는 것
    brand/   로고·인트로·워터마크
    refs/    생성에 반복해서 물리는 참조 (캐릭터 시트, 스타일 기준)
    music/   반복해서 쓰는 BGM
    fonts/
  episodes/<EP>/
    source/                   ← 이 편에서만 쓰는 것
      SOURCES.md              출처 기록장 (파일·종류·어디서·날짜)
      <원본 파일들>
```

**판단은 한 줄입니다. 다음 편에서도 쓸 것인가.** 그렇다면 `assets/`, 아니면 `source/`.
애매하면 `source/` 에 두고, 두 번째로 쓰게 될 때 옮기세요. 미리 공용으로 만들면 안 쓰는 것이 쌓입니다.

### 규칙

- **원본을 옮기지 말고 복사합니다.** 다른 프로젝트 폴더를 참조하면 그 폴더가 움직이는 순간 이 편이 깨집니다.
  용량이 아깝더라도 편은 자기 안에서 완결되는 편이 낫습니다.
- **출처를 `source/SOURCES.md` 에 적습니다.** 파일만 있으면 몇 주 뒤에 어디서 왔는지 모릅니다.
  AI 로 만든 것은 모델과 프롬프트도 남깁니다 — 같은 톤으로 하나 더 만들 때, 그리고 설명란에
  사용 모델을 밝힐 때 필요합니다.
- **미디어 파일은 git 에 올라가지 않습니다**(`.gitignore`). `assets/` 와 `episodes/` 는 따로 백업하세요.
- **`assets/` 의 파일은 지우거나 덮어쓰지 않습니다.** 지난 편을 다시 렌더하면 화면이 달라집니다.
  바꿔야 하면 이름을 새로 만들고 예전 것을 남겨 두세요.
- 중간 산출물(`public/`, `out/`, `narration_final/`)은 백업 대상이 아닙니다. 다시 만들 수 있습니다.
  **다시 만들 수 없는 것은 `source/`, `assets/`, 그리고 대본입니다.**

## 소재의 종류

계획서(`45_visual_plan.py`)의 **소재** 칸에 쓰는 값입니다.

| 값 | 무엇 | 언제 |
|---|---|---|
| `existing` | 이미 있는 파일 — 원본 클립, 스틸, 지난 프로젝트 자산 | **증거**를 보여줄 때 |
| `record` | 화면 녹화 — 터미널, 편집 화면, 브라우저 | **증거**. 도구가 실제로 도는 걸 보여줄 때 |
| `gen-video` | AI 생성 영상 | 재현할 수 없는 장면, 분위기, 비유 |
| `gen-image` | AI 생성 이미지 | 같은 이유. 움직임이 필요 없을 때 |
| `whiteboard` | 손그림 애니메이션 | 단계가 쌓이는 설명, 볼 실물이 없을 때 |
| `code` | Remotion 이 직접 그림 — 텍스트, 표, 도식 | 결론, 수치, 구조 |
| `none` | 소재 없이 화면만 | 텍스트 카드 등 |

**한 가지 원칙**: 증거로 쓰는 화면은 `existing` 이나 `record` 여야 합니다.
"이렇게 됐습니다" 하면서 생성한 그림을 보여주면 그건 증거가 아니라 삽화입니다.
생성물은 설명·분위기·개념 구간에 씁니다.

## 종류별로 구하는 법

### existing — 이미 있는 파일
그냥 `source/` 에 복사합니다. 원본은 건드리지 않습니다.
```bash
cp ~/projects/old/clip.mp4 episodes/E01_x/source/
```

### record — 화면 녹화
도구가 실제로 도는 화면은 재연보다 녹화가 낫습니다. 다만 **이미 로그가 남아 있다면 녹화할 필요가 없습니다** —
실제 출력을 텍스트로 저장해 두고 카드로 띄우면 재연이 아니라 진짜 출력입니다.

녹화할 때:
- 1080p 로 줄어드는 것을 감안해 터미널 글자를 평소보다 크게.
- 창을 전체화면으로 두고 마우스 움직임을 최소화.
- 길게 찍고 편집에서 자릅니다. 8초짜리를 만들려고 8초만 찍지 마세요.
- macOS 라면 OBS 나 `screencapture -v` 로 충분합니다.

### gen-video / gen-image — AI 생성
이 공정은 특정 생성 서비스에 묶여 있지 않습니다. 어디서 만들든 파일을 `source/` 에 두면 됩니다.
쓰던 도구(웹 UI, MCP, API)를 그대로 쓰세요.

지킬 것 두 가지:
1. **한 편 안에서 화풍을 통일합니다.** 컷마다 스타일이 다르면 한 편으로 안 읽힙니다.
   같은 모델, 같은 스타일 문구, 가능하면 같은 참조 이미지를 씁니다.
2. **생성 기록을 `source/` 에 남깁니다.** 어떤 모델·프롬프트로 만들었는지 적어 두세요.
   나중에 같은 톤으로 하나 더 만들어야 할 때와, 영상 설명란에 사용 모델을 밝힐 때 필요합니다.
   ```
   source/gen_manifest.md    # 파일명 · 모델 · 프롬프트 · 생성일
   ```

세로 쇼츠까지 만든다면 16:9 로 만들고 중앙을 잘라 쓰는 편이 안전합니다.
처음부터 9:16 으로 만들면 롱폼에서 못 씁니다.

### whiteboard — 손그림 애니메이션
별도 도구가 필요합니다(선택 — 안 쓰면 설치하지 않아도 됩니다).

```bash
bash pipeline/install_whiteboard.sh          # ~/.claude/skills/ 에 설치
# 또는 직접:
git clone https://github.com/miloveme/srt-whiteboard-animation.git
```
설치하면 Claude Code 에서 스킬로 부를 수 있고, 스크립트를 직접 실행할 수도 있습니다.
자체 파이썬 환경을 쓰므로 저장소 안에서 `python3 scripts/prepare_env.py` 를 한 번 돌립니다.

구간 자막을 뽑아 그 도구로 렌더하고, 나온 mp4 를 `source/` 에 둡니다.
```bash
python3 pipeline/80_whiteboard_srt.py E01_x --ids s06,s07
# 그 SRT 로 손그림 도구 실행 — 자막은 반드시 끄기(Remotion 이 이미 굽는다)
```
언제 쓰고 언제 쓰지 말지는 [런북](../skills/knowhow-episode/SKILL.md) 3단계에 있습니다.

### code — Remotion 이 그림
소재 파일이 없습니다. `scenes.tsx` 에서 카드를 고르기만 하면 됩니다.
결론·수치·구조는 대부분 여기가 낫습니다. 생성보다 빠르고, 글자가 정확하고, 나중에 고치기 쉽습니다.

## 넣는 법

`script/visual_prep.json` 에 적고 `15_clip_prep.py` 를 돌립니다.

```json
{
  "clips":  { "take_fail": "raw_take_a.mp4", "wb_s06": "whiteboard_s06.mp4" },
  "images": { "diagram": "sketch.png", "shot": "generated_scene.jpg" },
  "stills": { "take_fail": [0, 7, 12.9] },
  "crops":  { "hook_left": { "src": "hook_compare", "t": 7.8, "box": [0, 0, 960, 380] } },
  "contact":[{ "name": "contact_crop", "src": "take_fail", "every_sec": 1.5, "count": 9,
               "crop": [0.05, 0, 0.55, 0.7], "highlight": [3,4,5,6], "cell_w": 400 }]
}
```

- `clips` — 영상을 1080p 무음으로 변환합니다. 소리는 내레이션이 담당하므로 뺍니다.
- `images` — 가로 1920 이하로 맞춰 복사합니다.
- `stills` — 영상에서 정지 프레임을 뽑습니다. 전후 비교에 씁니다.
- `crops` — 그림의 **일부만** 잘라 새 파일로 만듭니다. 좌우가 한 장에 붙은 대조 소재에서
  한쪽만 썸네일·쇼츠에 쓸 때. `src` 는 클립이나 이미지의 키, `t` 는 클립일 때의 초,
  `box` 는 **변환본 픽셀** `[x0, y0, x1, y1]` 입니다.
  **부품에서 자르지 않고 여기서 파일로 만드는 이유** — 부품에서 자르려면 소재의 원본 크기를
  코드에 적어야 하고, 소재를 다시 자르면 그 숫자가 조용히 틀립니다. 화면이 안 깨지고
  **엉뚱한 자리가 멀쩡하게** 나오므로 사람 눈에 안 걸립니다.
  범위를 벗어난 상자는 PIL 이 검정으로 메우므로 `15_clip_prep.py` 가 거기서 멈춥니다.
- `contact` — 여러 장을 한 화면에 늘어놓습니다. 시간에 따른 변화를 한눈에 보일 때.

돌리고 나면 `remotion/public/<slug>/` 에 파일이 생기고, `scenes.tsx` 에서 그 이름으로 참조합니다.

```tsx
case "s00": return <ClipPlayer src="e01/take_fail.mp4" fromSec={0} label="원본" />;
case "s01": return <ImageCard mode="single" src="e01/contact_crop.png" ... />;
```

## 순서

1. 대본을 쓴다 → 승인
2. 음성을 만들고 시각표를 뽑는다 (씬 길이가 나온다)
3. `45_visual_plan.py` 로 계획서를 만들고 **카드·소재·준비할 것**을 채운다 → 승인
4. 계획서의 "준비할 것" 을 실제로 만든다 — 녹화하고, 생성하고, 복사한다
5. `visual_prep.json` 에 적고 `15_clip_prep.py`
6. `scenes.tsx` 를 쓴다 — 씬마다 `// card: <이름>` 을 위에 붙인다
7. `46_grammar_check.py <EP> --verify` 로 계획서와 구현을 대조한다

**4번을 3번보다 먼저 하지 마세요.** 계획 없이 소재부터 만들면 안 쓰는 것을 만들게 됩니다.
반대로 계획서의 "준비할 것" 을 비워 두고 5번으로 가면 렌더 직전에 막힙니다.

### 계획서는 만들고 나면 기록이 된다

만들면서 카드를 바꾸는 일은 늘 생깁니다. 그때 계획서를 같이 고치는 사람은 없습니다.
아무도 대조하지 않으면 계획서는 조용히 거짓말이 되고, 다음 편에서 그걸 보고 배웁니다.
실제로 한 편에서 카드 7개가 구현과 달랐고, 한 씬은 계획서·`grammar.json`·구현이
셋 다 달랐습니다.

그래서 구현이 자기 답을 적습니다.

```tsx
// card: table
case "s01":
  return <TableCard ... />;
```

`--verify` 가 이 선언과 계획서 표를 대조하고, 다르면 **4번으로 끝납니다**.
카드를 바꿨으면 계획서도 같이 고치라는 뜻입니다.

# 화면 녹화를 내레이션에 붙이기

구성된 화면(표·도식)은 자기 시간이 없어서 음성이 길이를 정한다.
**녹화는 다르다.** 0:12에 렌더가 시작되고 1:05에 에러가 뜬다 — 안쪽에 고정된 구조가 있다.
전 구간을 맞추려 하면 한쪽이 망가진다. 그래서 **몇 지점만 못 박고 사이를 늘였다 줄인다.**

## 하는 법

**1. 녹화에 앵커를 단다** — `source/<이름>.anchors.json`
```json
{ "anchors": [
  { "id": "render_start", "t": 12.4, "note": "렌더 시작" },
  { "id": "error",        "t": 65.1, "note": "에러가 뜬 지점" }
]}
```

**2. 어느 자막 줄에 붙일지 정한다** — `script/rec_sync.json`
```json
{ "s09": {
  "clip": "rec/blender.mp4",
  "anchors": "source/blender.anchors.json",
  "bind": [ { "anchor": "render_start", "line": 1 },
            { "anchor": "error",        "line": 3 } ]
}}
```
`line` 은 그 씬 자막의 몇 번째 줄인지다. **그 줄이 언제 발화되는지는 이미 안다** —
`50_captions_build.py` 가 문장·낱말 시각을 남겨 두었다.

**3. 돌린다**
```
48_rec_sync.py <EP>          # 구간표 계산 + 녹화를 public 으로 + 프리즈 프레임 추출
```

## 사이 구간을 채우는 세 가지

| 상황 | 처리 | 왜 |
|---|---|---|
| 조금 길다 | 배속 | 화면 녹화는 1.4배까지 아무도 눈치 못 챈다 |
| 많이 길다 | **잘라낸다** (기본 3배 초과 시) | 3배 넘으면 커서가 순간이동해 글리치로 보인다 |
| 짧다 | 최저 0.85배로 늦추고 끝에서 **멈춘다** | 화면 녹화 슬로우모션은 어색하다 |

건너뛴 구간과 배속은 화면 구석에 표시된다. 없으면 시청자가 자기 눈을 의심한다.

## 검사

`48_rec_sync.py` 는 조립 후 두 가지를 잰다.
- 앵커가 제 문장 시작에 정확히 붙었나
- 구간의 합이 씬 길이를 빈틈없이 덮나

음성이 화면을 정하는 다른 단계와 달리, 여기는 계산이 틀리면 **조용히 밀린다.**
그래서 검사가 같이 있다. 걸리면 종료코드 3.
